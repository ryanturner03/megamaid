# Analyze Snapshot

You are helping the user create a `converter.py` script that transforms megamaid accessibility tree snapshots into clean Markdown.

## Context

The user has run `megamaid suck` to crawl a website and save accessibility tree snapshots to disk. Each snapshot is a JSON file containing:

- `tree`: A text outline of the page's accessibility tree (indented, with element IDs like `[0-155]`)
- `urlMap`: A mapping of element IDs to URLs
- `imageMap`: A mapping of element IDs to image source URLs
- `url`: The original page URL
- `title`: The page title

The `site.json` manifest lists all captured pages.

## Your Task

1. **Read `site.json`** from `{{dir}}` to understand the crawl
2. **Read 2-3 sample snapshots** — pick the first, one from the middle, and the last to catch structural variation
3. **Analyze the tree structure** to identify:
   - Where the page title lives (usually `heading level=1`)
   - Where main content starts and ends
   - What to skip: navigation, sidebar, footer, cookie banners, feedback widgets, breadcrumbs
   - How links appear in the tree (element IDs that map to `urlMap`)
   - How images appear (element IDs that map to `imageMap`)
4. **Write `converter.py`** in `{{dir}}/` that:
   - Is self-contained Python 3 (no pip dependencies — stdlib only)
   - Reads snapshot JSON files from `snapshots/`
   - Converts each snapshot's tree to clean Markdown
   - Replaces element IDs with real URLs from `urlMap`
   - Replaces image element IDs with relative paths to `images/` directory
   - Has a `main()` with argparse: `input_dir`, `--out`, `--chunk`, `--chunk-size`, `--only`, `--dry-run`
   - Generates an `index.md` summary table
   - Handles `--chunk` with heading-aware splitting and YAML frontmatter per chunk
   - Handles `--only` to convert specific pages
   - Handles `--dry-run` to convert one page and print to stdout
   - Skips pages gracefully on error (log and continue)
5. **Run it** against one sample: `python3 {{dir}}/converter.py {{dir}} --dry-run`
6. **Show the user** the sample Markdown output for review

## Important Guidelines

- The tree text uses indentation to show hierarchy. Each line has format: `[frameOrdinal-backendNodeId] role: "name"` with optional properties like `level=1`
- Navigation elements typically have role `navigation`. Skip these.
- The main content is usually between the first `heading level=1` and the first `contentinfo` (footer) or `navigation` after content
- Links in the tree text look like `[0-155] link: "Click here"` — the ID `0-155` maps to a URL in `urlMap`
- Images look like `[0-200] image: "Alt text"` — the ID `0-200` maps to an image URL in `imageMap`
- For image local paths, use the pattern: `images/<page-name>/img-NNN.ext`
- Make the converter robust: if a snapshot has unexpected structure, log a warning and skip it rather than crashing
